A fix for a brightness change that could quietly go missing, and the groundwork that lets the app be translated — English is still the only language, so nothing on screen changes yet.

### Fixed
- **A brightness change made mid-apply no longer goes missing** — changing brightness while another change was still being applied (which in practice means moving both sliders in the same second) could leave the screen and the saved setting describing two different things. Committing a change both queues the work and wakes the app's own watcher, so two requests arrive together; the second one only ever checks the temperature, found it unchanged, and concluded there was nothing to do — taking the brightness with it. It did not fix itself either: every later check compared the same two unchanged values and reached the same conclusion, so the screen stayed wrong until the temperature changed or the machine resumed from suspend. The newer values still win, but a change you actually asked for is no longer cancelled by a check that ran behind it.

### New
- **The app can be translated** — every word it shows now comes from a message catalog rather than from the code, so adding a language means writing one file: no Rust, and no building the app. Anything a translation leaves out falls back to English message by message, so a partial translation is useful from the day it is started rather than only when it is finished. Message ids are checked against the English catalog when the app is built, so a typo becomes a build error instead of a blank label, and the catalogs travel inside the binary — the `.deb`, the flatpak and a plain `cargo build` all carry their translations with no packaging change. **English is still the only catalog, so this release looks exactly like the last one.** See [docs/translating.md](../translating.md) for how to add a language, including the two packaging files that carry the name and description your software center shows.

### Other
- Building the flatpak from a working tree no longer means hand-editing a second copy of the manifest and remembering not to commit it — [`flatpak/generate-local-manifest.py`](../../flatpak/generate-local-manifest.py) derives it from the real one, so permissions and build commands come from the manifest that actually ships. The instructions for regenerating `cargo-sources.json` were also wrong in a way that failed quietly: they said a diff against the last release tag could tell you to skip it, which a gitignored file and an uncommitted change both make untrue. Regenerate before each build.

## Install

1. Download **`cosmic-nightlight_0.5.1-1_amd64.deb`** from the Assets section below.
2. Open the downloaded file with the **COSMIC Store** and click **Install**.
   (Or from a terminal: `sudo apt install ./cosmic-nightlight_0.5.1-1_amd64.deb`.)
3. Add the applet to your bar: **COSMIC Settings → Desktop → Panel** (or
   **Dock**) **→ Configure applets → Add applet → Night Light**.

A flatpak bundle — **`cosmic-nightlight-0.5.1.flatpak`** — is attached as well, for trying the sandboxed build before it reaches the COSMIC Store: `flatpak install --user ./cosmic-nightlight-0.5.1.flatpak`. The `.deb` above is still the supported route.
