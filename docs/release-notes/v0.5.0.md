The schedule can now follow the real sun rather than times you type, and the app can ship as a flatpak — which is what makes a COSMIC Store listing possible — setting itself up the first time you turn it on rather than making you find a setup step.

> ℹ️ **Nothing changes if you use the `.deb`.** The package installs the helper and the polkit rule as it always has, and none of the flatpak setup below ever appears. Everything under that heading is about the sandboxed build.

### New
- **"Sunset to Sunrise", off the actual sun** — a third schedule option beside Off and Custom Schedule, and the one that needs nothing set: the tint starts at real sunset where the machine is and lifts at real sunrise, moving with the season on its own. The location comes from the time zone you have already configured, looked up in the tz database that is on disk anyway and turned into today's sun in process — which is what `cosmic-settings-daemon` does for its light/dark switch. Every other way of finding a location is a worse trade for a night light: a location service is another daemon and another permission, a network lookup spends privacy on a screen tint, and asking for coordinates is the chore this mode exists to remove. A time zone places you within a few hundred kilometers, which moves sunset by minutes. Where there is no location to work from, or at a latitude where the sun doesn't set that day, it falls back to the times in the pickers and says which of the two happened — a schedule you asked for never silently does nothing.
- **Flatpak support** — warming the screen means writing gamma LUTs to DRM, which needs DRM master, which needs `CAP_SYS_ADMIN`. No flatpak permission grants that, so a sandboxed build cannot tint the screen itself no matter how it is configured. The applet instead reaches a privileged helper on the host through `flatpak-spawn` and `pkexec`. See [docs/flatpak-design.md](../flatpak-design.md) for why it is built this way.
- **Sets itself up on first use** — the host helper has to exist before the sandboxed app can be silent, and a flatpak cannot install it. Until it is installed, *every* tint change costs a password prompt — so the first one is spent installing it as well as applying the change. One prompt, and then none. There is no setup step to find and no wizard to sit through.
- **A settings row, when there is something to do** — offers that same setup if the first prompt was dismissed, and offers to replace the installed helper when a release has genuinely changed what the app asks of it. It only exists while one of those is true, and it disappears by itself once handled, without restarting the app.
- **A schedule with nothing to run it now says so** — the app keeps to its schedule through the applet on your panel, or while the settings window is open. Without the applet, closing that window left the screen stuck at whatever it last was: the next sunset never arrived, and nothing on screen explained why. The settings window now notices, and offers the two ways out — add the applet, or run it in the background. It appears only when there is genuinely a schedule set and nothing around to honor it.
- **"Run in Background", where it is needed** — under a Background heading of its own, it runs the headless scheduler for people who would rather not keep the applet on a panel, so that no longer means a terminal. It starts one immediately as well as at each login, and turning it off stops the running one within a few seconds — the setting is about a process that exists now, not only about tomorrow's login, which is why it isn't called "start on login". The 0.4.0 toggle by that name was removed because it duplicated what the applet already did for everyone who had one; this one appears only when the applet is absent. Turn it on and later add the applet back, and it retires itself — the background process stops and the setting disappears, because the applet is now doing that job. It only ever stays on screen if turning it off failed, which is worth saying out loud.
- **`--version` on the helper** — reports the version of its *command line* rather than of the app, so a GUI can tell whether a helper installed by an earlier release still understands it. Keying this to the app version would have meant a password prompt on every update; keying it to the arguments means it is asked for only when something genuinely changed.
- **An app icon and AppStream metadata** — the app describes itself to software centers with an icon of its own, instead of borrowing one from the icon theme that not every theme has.
- **The temperature slider runs the way it reads** — its track is now warmth rather than Kelvin, so dragging right warms the screen and a fuller bar is a stronger tint. It used to run on the Kelvin number directly, which meant dragging right made the screen *cooler* and a full bar meant no tint at all. **Less warm** and **More warm** now sit under the ends, because the number alone never said which way was which — "2500" reading as more orange than "6500" is not something to make anyone work out. The Kelvin readout stays, since it is the number worth knowing.
- **Popups and windows follow the theme, frosted glass included** — the applet popup takes its padding, corner radius and blur from whatever the active theme says applet surfaces should look like, rather than a fixed set of its own. With frosted glass turned on, the app now frosts along with the rest of the desktop instead of sitting flatly opaque in the middle of it.

### Fixed / hardened
- **One password prompt per change, not one per open window** — the applet and the settings window each apply changes themselves, so that the night light follows its schedule whichever part of the app happens to be running. They already shared a lock and a record of what is on screen, so only one of them ever did the work — but a *dismissed* prompt was remembered only by the process that had asked, and the other one was already queued up behind it. Turning the night light on with both windows open therefore asked twice, until the first successful authentication. A refusal is now recorded where all of them can see it.
- **Cancelling a password prompt cancels what was waiting behind it** — while a prompt was up you could still move the temperature and brightness sliders and choose a schedule, and each of those queued privileged work of its own. Dismissing the prompt then let them through one after another, so a single "no" could be followed by three more dialogs. Everything privileged now waits on the same lock — the schedule's setup used to run beside an apply rather than after it, which is what made the dialogs pile up on screen together — and a refusal answers every change that was already waiting on it. Changing something *after* dismissing a prompt still works immediately, which is what makes an accidental dismissal cheap to recover from.
- **Uninstalling actually removes everything** — `uninstall.sh` now removes a flatpak install as well (which `apt remove` knows nothing about), un-registers the panel applet so `cosmic-panel` stops restarting it into a dead gap, and resets the screen tint using whichever helper it can still find rather than leaving the screen warm with nothing left to fix it.
- **A release cannot ship a mismatched version** — the version lives in `Cargo.toml`, `debian/changelog`, and the AppStream metadata, and only the changelog one used to be checked. A stale metainfo version would have shown the previous version on the Store page while serving the new build, silently. `scripts/check-version.sh` now fails the release, and can be run before tagging.
- **The flicker note is in both places** — it sat under the temperature slider in the applet popup but not in the settings window, where the same slider is.
- **Only something you did can raise a password prompt** — a change you just made may spend one; a verdict nobody asked for may not. A schedule boundary, a resume from suspend, or a snapshot read at startup now stays quiet on a host that has not been set up, rather than putting a dialog on screen at sunset with nobody in front of it. A force-on that the missing setup makes undeliverable is dropped on the same rule, so settings that outlive an uninstall cannot conjure a prompt of their own accord.
- **The applet stops fighting the settings window for the screen** — its tick reconciled the screen against a snapshot it had not re-read, so once that snapshot drifted from what was stored the two would each push their own idea of the tint, every tick. The tick now re-reads first. A slider being dragged still owns its handle until it is released.

## Install

1. Download **`cosmic-nightlight_0.5.0-1_amd64.deb`** from the Assets section below.
2. Open the downloaded file with the **COSMIC Store** and click **Install**.
   (Or from a terminal: `sudo apt install ./cosmic-nightlight_0.5.0-1_amd64.deb`.)
3. Add the applet to your bar: **COSMIC Settings → Desktop → Panel** (or
   **Dock**) **→ Configure applets → Add applet → Night Light**.
